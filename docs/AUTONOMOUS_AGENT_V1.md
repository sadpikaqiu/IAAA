# IAAA 自主 Agent v1

本版本把工具选择、候选保留、查证和停止交给 Qwen3.8-27B；保留 intention–affordance 输出。
图片来自已完成的 Flash 摘要，评论/图片使用冻结快照与现有字符 TF-IDF。推荐过程中不调用外部识图 API。

## 引擎

| 引擎 | 行为 |
|---|---|
| fixed (A) | 原 P4v1 固定流程 |
| fixed_llm_rank (B) | A 的同一意图、扩展决定和最终候选，改用公共 LLM 排名器 |
| fixed_schedule (C) | 新状态/候选管理与排名器，程序固定工具顺序，模型填写参数与候选选择 |
| autonomous (D) | 模型自主选择工具、顺序、参数、查证与提前停止 |

C 的固定顺序为历史/空间、转移/时段、类别/相似用户、外部证据与候选检查、空间/类别扩展、候选整理。
轨迹模式在第四轮只检查结构化候选。最后一次扩展固定 radius=20 km、limit=50。
C 与 D 的实际调用数可不同，预算上限相同；不能把它们称为完全等算力对照。

## 数据与决策边界

`VisibleQuery` 不包含目标 POI、目标类别或目标坐标。查询只提供用户、目标时间、可见历史与上下文。
工具白名单包含历史读取、六路召回、证据检索/读取、候选事实检查和候选分页。
模型没有 shell、任意文件或网络工具，评论中的文本不作为指令。

候选登记表保留所有已发现候选及来源；模型维护的比较集合最多 60 个。离开比较集合不会删除登记记录。
工具使用源内检索排序，不把相关度归一化叠加成全局推荐分数，也不强行预留多模态名额。
最终排名必须来自比较集合，输出 10 个不同 POI、五种核心 affordance 判断、理由和合法引用。
新输出为 schema_version=2，没有人为制造 alignment_score 或旧分数分解。

外部证据仍是日期未知的静态侧信息：评论为访客报告、图片摘要为模型观察。不可声称实时营业、价格、设施或场景已经得到验证。
目录元数据沿用原 transductive catalog；访问次数和转移只来自当前历史划分及可见上下文。
全局历史划分沿用每用户比例，不改为全局日历时间切分。

## 预算、格式与恢复

- 最多 6 次决策；前 5 次可调用工具，最后一次只整理候选。另有 1 次最终排名。
- 每轮最多 3 次工具调用，总计最多 12 次；可提前停止。
- 决策输出 2048 tokens，排名输出 4096 tokens；输入使用本地同模型 tokenizer 计数，预算 11500 tokens。
- 输入为修复提示预留最多 1024 tokens；压缩工具结果时保留候选检查的时段、转移、来源等全部事实字段。
- 候选登记表达到 10 个后，每轮必须保留至少 10 个不同的比较候选，防止最后一轮只剩少数候选却要求输出 10 个。
- 修复提示包含具体重复 ID、位置、不同 ID 数量及上一版错误答案；若上下文较长则缩为 ID 摘要，原始事实不删除。结果仍须通过原有唯一性、候选范围与引用校验，不自动补齐排名。
- 新决策/排名使用 JSON Schema 约束；未知 ID、重复排名和跨 POI 引用仍由程序校验。
- 自主决策的生成 Schema 使用两个完整分支约束控制行为：继续必须有至少一个工具，停止必须为空工具列表，字段不得省略。候选不足时只允许继续，预算收尾时只允许停止；模型可在候选充足时提前停止，不必等到第六轮。
- C 的工具名、顺序和停止由程序派发，模型只生成参数，避免把固定对照误做成自主调度。
- 请求超时 180 秒、会话期限 1200 秒；每会话最多 2 次额外修复/重试。失败不使用启发式预测兜底。
- 日志记录每次请求、响应、错误、usage、工具结果、候选变更和停止原因。有效请求可复用，已开始但中断的请求仍占重试预算。
- 日志以协议、消息和参数哈希校验；恢复时重放确定性本地工具来重建状态，不重复成功的模型请求。

真实模型开发测试发现自由 JSON 下固定对照会改选工具、候选列表可能超过 60；现已使用程序调度和结构约束解决，失败开发记录单独保留。

```bash

  --user-id 652 --trajectory-id 652_38 --train-ratio 0.7 \
  --data-dir /home/yzj/IAAA/datasets/NYC \
  --engine autonomous \
  --evidence-snapshot /home/yzj/IAAA/outputs/experiments/mm_pipeline_20260914/evidence/NYC_53c3456f6380.json \
  --tokenizer-path /home/yzj/Model/Qwen38-27B \
```

## 配对实验

入口 `scripts/evaluate_autonomous.py`：

1. 核对原引擎统计模块哈希、旧报告、CSV、证据快照和原全量会话标识。
2. 从每用户 [70%,80%) 中排除旧消融 500 会话，按 `iaaa-autonomous-v1` 哈希选每城 50 个开发会话及另外 500 个验证会话。
3. 两城开发与独立验证运行 A/B/C/D × text/both 八组；固定 100 个验证会话额外重复 D 两种输入各一次。
4. 验证质量通过后自动运行 D 两组：NYC 50 → NYC 3976 → TKY 50 → TKY 11664。烟测结果复用于全量，不重复请求。
5. 旧全量 A 直接复用。只补跑 TKY 图文异常 `1989 / 1989_33`，修正版注明来源与新增成本；原报告不改动。

修复版本可用 `--baseline-repair-source <旧结果目录>` 复用已验证的 TKY 异常修复结果；核对模型、数据、旧统计代码和结果哈希，不重复模型请求。

同一阶段所有组使用相同会话。B 每会话复用 A 的候选与意图。正式质量门槛要求会话/组别完整、无预测兜底、usage 完整。
若达到 4 个失败会话，停止新增请求并保存失败汇总。恢复使用原命令；代码或配置改变需要新输出目录。

独立验证的 A 是新增会话上的首次运行，不能用旧 500 消融或旧全量的分数代替；原全量 A 不整轮重跑。

### 时间戳相同的三个会话

原 TKY 全量中的 `872_26`、`1762_38`、`1762_39` 各有一个上下文签到与目标时间戳相同，没有更晚记录，训练历史均严格更早。
为保持原配对协议，主结果沿用给定会话顺序并标记该情况；同时生成去掉这 3 个会话的 strict_time_sensitivity 报告。
不利用同时间戳事件的目标类别或位置来调整顺序。

## 结果和成本

结果目录包含：

- manifest.json：代码、模型、tokenizer、数据、快照、样本与统计协议。
- progress.json：当前阶段、已完成/失败数、活跃调用的心跳。
- runs/：每组逐会话预测、请求缓存和状态；cases/：标签仅在预测后关联的配对记录。
- reused_baselines/：异常恢复来源与修正版指标。
- summaries/ 和 REPORT.md：开发、验证、全量、时间边界敏感性和主要比较。

报告 Hit@1/5/10、NDCG@10、MRR@10、各层候选召回、IH/OOH、失败阶段、工具使用、引用、tokens 和耗时。
95% 区间采用用户聚类 bootstrap 2000 次；主要 Hit@10 比较采用用户成组交换的置换检验 10000 次及 Holm 校正，seed=42。
验证与全量各自定义检验族，不跨历史比例合并结果。

B 的独立运行成本含 A 的共享意图调用，物理请求汇总只计实际请求一次，包含失败/中断尝试。
旧全量缺少逐会话耗时/token 和原始候选数量，标记不可用；不通过均分总量或填零伪造明细。
引用 ID/归属验证通过不等于语义判断已被验证，需要结合案例检查。

## 后台运行

```bash
screen -dmS iaaa-autonomous-fix02-0921 bash scripts/run_autonomous_screen.sh \
  /home/yzj/IAAA/outputs/experiments/autonomous_v1_20260921_fix02
```

先核对 `screen -ls` 和 progress.json，避免重复启动。查看：

```bash
tail -f /home/yzj/IAAA/outputs/experiments/autonomous_v1_20260921_fix02/runner.log
```

离线重建报告：`python scripts/report_autonomous.py --results <结果目录>`，不调用模型。

启动脚本用 `tee` 同时显示 screen 输出并保存日志，并自动打开 `progress` 窗口，每 10 秒读取已有 progress.json 显示阶段、完成/失败数、各会话当前组别和步骤，以及最近事件距今时间。开发/验证阶段必须完成一个会话的全部对照组，完成计数才增加，因此长时间未增加不等于模型没有工作。

`Ctrl-a` 后按 `0` 查看 runner 日志，按 `1` 查看进度，按 `d` 脱离 screen。只读查看器可单独运行：

```bash
python scripts/watch_autonomous.py <实验根目录> --interval 10
```

查看器不调用模型、不修改结果；PID 和事件时间用于判断保存的进度是否仍在推进。实验停止后窗口保留，方便查看最终状态。新版固定输出目录与旧版本隔离，旧失败记录保留。
